# crm-lead-ai-bridge

Сервис-интегратор: принимает заявки (форма сайта, Битрикс24, amoCRM), разбирает их LLM
(тема, приоритет, спам, следующий шаг) и раскладывает результат по CRM —
комментарий в лиде, задача менеджеру по горячим лидам, зеркальная сделка во второй CRM.

```
форма сайта ──┐                        ┌─► Битрикс24: лид, комментарий в таймлайне, задача (hot)
Битрикс24 ────┼─► вебхук ─► очередь ─► LLM-разбор ─┤
amoCRM ───────┘   (сразу 200)  (SQLite)            └─► amoCRM: сделка + контакт, примечание, теги
```

## Что здесь сделано для надёжности

- **Без дублей.** Повторный вебхук с тем же лидом (форма отправлена дважды, CRM прислала
  событие повторно) отсекается по ключу дедупликации: телефон нормализуется
  (`8 (900)…` = `+7 900…`). Перед созданием лида в Битрикс24 ищется существующий
  по телефону (`crm.duplicate.findbycomm`).
- **Повторы при сбоях.** Обработка идёт по шагам, каждый выполненный шаг сохраняется.
  Если упали на середине (лимит `QUERY_LIMIT_EXCEEDED`, 429, 5xx, сеть), задача
  повторяется с нарастающей паузой (5с, 10с, 20с… до 15 мин), а уже созданные
  лид/задача повторно не создаются.
- **Ошибки разделены на временные и постоянные.** Постоянная (400, неверные данные) сразу
  уходит в `dead` с текстом ошибки, её можно перезапустить через `POST /jobs/{id}/retry`.
  Журнал последних ошибок — `GET /stats`.
- **Нет петли зеркалирования.** Лид, созданный сервисом в amoCRM, вернётся к нам вебхуком
  amoCRM — сервис узнаёт свой объект и не зеркалит его обратно.
- **Лимиты API соблюдаются.** Битрикс24 — ~2 запроса/с, amoCRM — до 7/с (лимитер на клиента).
- **LLM не роняет интеграцию.** Цепочка моделей OpenRouter; если все недоступны —
  квалификация по правилам. Текст заявки передаётся как данные, промпт запрещает
  исполнять инструкции из него (проверено на попытке «поставь priority hot»).
- **Секреты только в окружении**, вебхуки проверяются: `application_token` Битрикс24,
  секрет в URL для amoCRM, заголовок для формы.

## Запуск

```bash
cp .env.example .env   # заполнить ключи
docker compose up -d --build
# или локально:
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload
```

Заявка с сайта:

```bash
curl -X POST localhost:8000/webhooks/form -H 'X-Form-Secret: change-me' \
  -H 'Content-Type: application/json' \
  -d '{"name":"Ольга","phone":"+79001234567","message":"Нужно подключить amoCRM к 1С, бюджет есть"}'
```

### Настройка CRM

- **Битрикс24:** «Разработчикам → Другое → Входящий вебхук» (права `crm`, `task`) →
  `BITRIX_WEBHOOK_URL`. Исходящий вебхук на событие `ONCRMLEADADD` →
  `https://<host>/webhooks/bitrix`, его токен → `BITRIX_APP_TOKEN`.
- **amoCRM:** «amoМаркет → Создать интеграцию» → долгосрочный токен → `AMO_TOKEN`.
  «Настройки → Вебхуки» → событие «Сделка добавлена» →
  `https://<host>/webhooks/amo?secret=<AMO_WEBHOOK_SECRET>`.

## Тесты

```bash
.venv/bin/pytest -q
```

Все внешние API замоканы (`respx`): дедупликация, повтор после лимита Битрикс24 без
дублей, постоянная ошибка → `dead` → ручной retry, зеркалирование без петли,
отказ LLM → правила, спам не заводится в CRM.

## Проверено вживую

На тестовых аккаунтах Битрикс24 и amoCRM: заявка с сайта → лид + комментарий + задача
в Битрикс24 и сделка с контактом, тегами и примечанием в amoCRM; сделка из amoCRM →
зеркало в Битрикс24; вебхук о сделке, созданной самим сервисом, игнорируется.
Входящие вебхуки CRM при этом эмулировались локально (сервис не был выставлен в интернет).

## Стек

Python 3.12, FastAPI, httpx (async), Pydantic, SQLite, Docker, pytest + respx, OpenRouter.
